# SIH26159 System Inventory & Baseline Analysis

## 1. Executive Overview
The SIH26159 problem statement requires an enterprise-grade Network Forensic Analysis and Threat Detection Platform specialized for email protocols (SMTP, IMAP, POP3) over TLS and STARTTLS. It must parse raw PCAP and PCAPNG traffic, reconstruct TCP streams, analyze protocol negotiations, inspect TLS handshakes, parse X.509 certificates down to cryptographic parameters, evaluate rule catalogs, score risks, detect anomalies (separating factual observations from threat inferences), generate comprehensive verifiable audit trails, provide AI-assisted risk reasoning with strict claim-checking against PCAP ground-truth, and produce full 13-section reports (JSON, interactive HTML, and PDF).

## 2. Baseline Inventory & Pitfalls Addressed
| Component | Common Baseline Defect in Prototype Scripts | Enterprise SIH26159 Target Implementation |
|---|---|---|
| **PCAP Ingestion** | Fails on PCAPNG, nanosecond timestamps, Linux Cooked SLL (113), or 802.1Q VLAN tags | Universal binary reader handling Classic PCAP (microsecond & nanosecond, big & little endian) and PCAPNG (SHB, IDB, EPB) with Ethernet, SLL, SLL2, and 802.1Q VLAN framing. |
| **TCP Reassembly** | Assumes in-order delivery; crashes on retransmissions, duplicate segments, sequence wraparound, and packet fragmentation | Strict stateful TCP stream reconstructor with sequence tracking, duplicate/overlap clipping, sequence wraparound handling (RFC 793), and byte-accurate packet-to-stream timeline mapping. |
| **STARTTLS Engine** | Naive string matching on "STARTTLS"; misses stripped advertisements, false OKs, or downgrade fallback | Formal protocol state machine for SMTP (RFC 3207), IMAP (RFC 2595), and POP3 (RFC 2595) classifying verdicts: `clean_starttls`, `ack_without_tls`, `missing_starttls_in_caps`, `rejected_starttls`, `fallback_to_plaintext`, `encrypted_implicit_tls`, `plaintext_unencrypted`. |
| **TLS Analysis** | Only looks at record version, missing extensions like SNI or supported_versions, ignoring cipher security details | Handshake parser extracting ClientHello (SNI, supported_versions, cipher suites), ServerHello, and Certificate messages; comprehensive IANA cipher database detailing Key Exchange, PFS, Symmetric Cipher, MAC, and Security Status. |
| **X.509 Cryptography** | Relies on external OpenSSL subprocesses or mock strings | Fully native ASN.1 DER parser reading Subject, Issuer, Validity (notBefore/notAfter, expiration calculation), SANs, Public Key Algorithm & Key Length (e.g. RSA 1024 vs 2048), Signature Algorithm, and Self-Signed heuristics. |
| **Risk Scoring & Anomaly** | Arbitrary numbers without CVSS alignment | Deterministic CVSS v3.1 aligned risk scoring with five severity tiers (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFORMATIONAL`); strict separation of "Observed Fact" from "Interpreted Threat". |
| **AI Layer** | Leaks PII/passwords, accepts LLM hallucinations of nonexistent ciphers or fake dates | Data minimisation pipeline (scrubs credentials, email bodies, strict IP masking); Gemini 3.8 Flash model invocation via server-side `@google/genai`; Claim-Checker validating that every cited cipher, version, and frame exists in the PCAP; deterministic fallback when offline or no API key. |
| **Forensic Integrity** | Simple timestamps without tamper proofing | Cryptographic SHA-256 hash chaining of audit logs (`prevHash + currentRecord -> currentHash`), re-hash verification endpoint, and tamper detection tests. |
| **Reporting** | Superficial text summaries | Full 13-section report generator exporting to structured JSON, XSS-sanitized HTML, and downloadable PDF with Executive Summary, Threat Matrix, and MITRE ATT&CK mapping. |
